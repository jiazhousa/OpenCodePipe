# Impl: Story 3 —— B 仓 CLI 工具族（ocp 命令 + pre-push 强制 + check-tools）

## 技术方案

### 总体策略

四部件沿 `cli/`（命令骨架）+ `check-tools/`（检查核心，纯逻辑可独立测）+ `configs/`（数据与词表）+ `scripts/`（vendored 同步）分工。任务切分四块：**块A CLI 骨架+init+doctor+worktree（先行）→ 块B pre-push ∥ 块C check-tools ∥ 块D vendored 机制（三块并行，文件集不相交）**。

### 决策记录

| # | 决策 | 内容与理由 |
|---|---|---|
| D1 | CLI 结构 | `cli/index.ts` 手写路由（命令表 + `process.argv` 解析 + `--help`）；子命令实现 `cli/commands/`（init.ts / doctor.ts / worktree.ts / check.ts / hook.ts）。**块A 建立全部五个命令文件的极简 stub**（`console.error("块X 交付")` + exit 1），B/C 块重写填充——保证块A 提交可编译、后续块文件所有权清晰 |
| D2 | hook 形态 | 校验逻辑 = `ocp hook pre-push` 子命令（cli/commands/hook.ts，读 stdin refs）。`.git/hooks/pre-push` 生成物为 shell 薄壳：**优先 `exec ocp hook pre-push "$@"`**（bin 可用时）；探测不到 ocp 则写 **`exec bun <B仓绝对路径>/cli/index.ts hook pre-push "$@"`**（本地开发模式）。生成时探测、幂等覆盖、文件头 `# generated by ocp init --hook` |
| D3 | pre-push 输入解析 | stdin 每行 `<local_ref> <local_sha> <remote_ref> <remote_sha>`；diff 文件集 = `git diff --name-only <remote_sha>..<local_sha>`；remote_sha 全零（新分支）时降级为 `git diff --name-only <local_sha>~1..<local_sha>`（保守：只查最近 commit）并 WARN。**只依赖 git 原生输出** |
| D4 | 代码白名单优先级（吸收复审 medium） | `configs/prepush-config.json`：`codePatterns`（默认 `src/** tests/** scripts/** cli/** check-tools/** agents/** configs/** package.json tsconfig.json bun.lock`）+ `archivePrefix`（`.specpipe/`）。**优先级：白名单命中即代码——`agents/**` 与 `configs/vendor/**` 中的 .md 以白名单为准**（权限与契约文件是行为载体）；其余 `.md`/`README`/`docs/**` 为档案类 |
| D5 | pre-push 校验核心 | `cli/commands/hook-core.ts`（纯函数，输入 diff 文件清单 + 仓库根，输出放行/拒绝+原因）：① 全档案 → 放行；② 含代码 → 提取 topic 集（正则 `^\.specpipe/plans/([^/]+)/`）→ **Eopic 判定 = 目录含 `epic-spec.md`** → Epic topic 跳过；Story/Issue topic 校验 `.stage===DONE`（不存在 .stage 视为未完成→拒）+ `.stage-history` 存在则核含 `"to":"DONE"` 且 `"from":"QUALITY_GATE"` 行（增强校验），不存在放行（存量豁免，**输出 WARN 一行**）；③ 代码无 topic → WARN 放行。拒绝时输出违规 topic 清单 + 指引（完成质量门或 `--no-verify`） |
| D6 | vendored 副本 | `configs/vendor/specpipe/07-state-machine.md` + `configs/vendor/specpipe/templates/*.md`（九件）入库；`transition-table.json` 新增 `vendor` 段：`{ repo, commit, files: { "<相对路径>": "<sha256>" } }`（07 卷必录，templates 逐件录）。副本由 vendor-sync 生成（本 Story 首次执行即产出） |
| D7 | 边集快照 | `configs/transition-snapshot.json`：`{ source: "<A仓commit>", states: [...18], transitions: [...25+3] }`——从 S2 `tests/table.test.ts` 的硬编码期望常量**机械提取**（一次性脚本或手工搬运后与测试常量 diff 核对，保持测试常量不动——测试仍是第一道对账，快照供 check 工具第二道） |
| D8 | vendor-sync | `scripts/vendor-sync.ts`：参数 `--path <本地A仓>` 或 `--tag <git tag>`（tag 时 clone 到临时目录）；复制 07 卷 + templates 九件 → 重算 sha256 更新 `transition-table.json` vendor 段与 source → **自动运行快照对账核心**：07 卷哈希变了而边集未适配 → 非零退出 + 输出"契约已变，边集需人工适配（开 B 仓 Story/Issue 走审查）" |
| D9 | check-tools 结构 | `check-tools/` 每项一个纯逻辑模块 + `cli/commands/check.ts` 薄路由（`ocp check <name>`）：`whitespace.ts` / `line-budget.ts` / `commit-format.ts` / `transition-consistency.ts` / `platform-words.ts`；`check-tools/task-yaml.ts` 占位（S5 预留，export 空对象 + 注释）。全部可独立 import 测试，check.ts 只做参数解析与调用 |
| D10 | whitespace 规则 | 扫描 `codePatterns` 范围的文本文件：尾随空白（行末空格/Tab）+ 文件末尾缺换行；规则硬编码（简明无争议），路径范围沿用 prepush-config 的 codePatterns（单一配置源） |
| D11 | line-budget 规则 | `configs/line-budget.json`：工件 glob → 上限行数（默认按 06-artifacts：`spec.md≤300`、`epic-spec.md≤500`、`issue-impl.md≤80`、`reviews/*.md` 上限 40/30 按类型——简化为 `reviews/**≤120` 兜底）；扫 `{wf}/plans/` 与 `{wf}/reviews/`，超限 FAIL 报文件+行数+上限。取终稿口径（宽松），草案阶段不检（工作流自管） |
| D12 | commit-format 规则 | `ocp check commit-format [--range HEAD~3..HEAD]`（默认 HEAD 单条）：首行格式 `<type>: <中文描述>`，type ∈ {feat, fix, docs, chore, refactor, test, style}（可配置 `configs/commit-format.json`）；非 ASCII 中文描述存在性（至少一个 CJK 字符） |
| D13 | transition-consistency | 三层（spec 规则 2）：① vendored 07 卷重算 sha256 vs transition-table vendor 段声明；② 数据文件 schema 自校验（状态引用完整性/initial 存在/terminal 存在/边引用的状态都存在）；③ 快照对账（snapshot states/transitions ⊆ 数据文件 且 ⊇，双向）。输出逐项 PASS/FAIL |
| D14 | platform-words | `configs/platform-words.json`：`{ words: [...内置词表], extraWords: [...] }`——内置初始集：`opencode`（小写独立词）、`subagent`、`SKILL.md`、`~/.config/opencode`、`permission.external_directory`、`task` 工具名等 opencode 专属词汇（词形边界匹配，大小写敏感词独立列）；扫 `--path`（默认 vendored 07 卷 + templates 九件）；命中报文件:行号:词。A 仓正文现状应零命中（S1 基线） |
| D15 | doctor 检查项 | 各项探测返回 `{name, level: PASS/WARN/FAIL, message}`：git 版本 / opencode 版本与 plugin 段挂载（全局+项目 opencode.json）/ agents 五文件（全局+项目）/ 检索三通道（读用户配置声明 + `which` 探测）/ vendored 状态（复用 D13 核心 + 本地 A 仓路径对比提示）。输出对齐表格。**只报告不安装** |
| D16 | init 铺设物 | `{wf}/plans/`、`{wf}/reviews/`、`{wf}/templates/`（vendored 九件复制）、**fence 脚本模板** `scripts/fence.sh`（最小骨架：typecheck/test 两步占位 + 注释指路"按技术栈改写"）、`.gitignore` 追加 `test-fence-reports/`（幂等）、`--hook` 装 D2 薄壳。已有文件/目录跳过并报告 |
| D17 | worktree | `ocp worktree <branch>`：三级格式校验 `^(dev|rel|ms)/(feat|fix|chore)/[a-z0-9-]+$`（目标集与性质集可配置 `configs/worktree-config.json`）；通过后在可配置专用目录（默认 `../.ocp-worktrees/`）创建 `git worktree add`；输出后续指引 |
| D18 | fence 挂载 | `scripts/run-test-fence.ts` 步骤表追加第四步 `consistency`（调 check-tools/transition-consistency 核心，不改 D2 三步语义，只增步骤） |

### 时序

## 风险

| 风险 | 缓解 |
|---|---|
| pre-push stdin/diff 边界形态（新分支全零 sha、tag 删除等） | D3 保守降级 + WARN；验收 5 覆盖常规三情形，奇异形态遇一修一 |
| hook 在无 bun/ocp 环境失效 | D2 生成时探测 + 薄壳 `command -v` 兜底提示（不静默失败） |
| 白名单/档案边界争议（configs/vendor 算代码） | D4 优先级显式声明（白名单命中即代码）+ 可配置 |
| vendor-sync 首跑哈希与 S2 手写 source 不一致 | 首跑后核对 transition-table vendor 段与 A 仓 HEAD 一致（验收含） |
| check 词表/规则初版偏严误报 | 全部可配置（configs JSON）；FAIL 输出具体文件行号便于豁免判断 |
| fence 第四步增加收尾时长 | consistency 纯内存计算（读两 JSON + 哈希一文件），秒级 |
