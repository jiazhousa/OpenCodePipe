## 技术方案

### 总体策略

四部件沿 `cli/`（命令骨架）+ `check-tools/`（检查核心，纯逻辑可独立测）+ `configs/`（数据与词表）+ `scripts/`（vendored 同步）分工。任务切分四块：**块A CLI 骨架+init+doctor+worktree（先行）→ 块B pre-push ∥ 块C check-tools ∥ 块D vendored 机制（三块并行，文件集不相交；全量 fence 在块D 收尾后才可四步齐跑）**。

### 决策记录

| # | 决策 | 内容与理由 |
|---|---|---|
| D1 | CLI 结构 | `cli/index.ts` 手写路由（命令表 + `process.argv` 解析 + `--help`），**首行 `#!/usr/bin/env bun` + 可执行位**（bin 形态要求）；子命令实现 `cli/commands/`（init.ts / doctor.ts / worktree.ts / check.ts / hook.ts，**块A 全部新建**，其中 check.ts / hook.ts 为极简 stub，块B/C 重写填充）。退出码约定全命令统一：0=成功 / 1=检查失败 / 2=用法错误 |
| D2 | hook 形态 | 校验逻辑 = `ocp hook pre-push` 子命令。`.git/hooks/pre-push` 生成物为**钉死的薄壳模板**：`#!/bin/sh` 首行 + 运行时探测——`command -v ocp` 优先 `exec ocp hook pre-push "$@"`；回退 `command -v bun` 时 `exec bun <B仓绝对路径>/cli/index.ts hook pre-push "$@"`；**均不可用 → echo 警告"ocp/bun 缺失，跳过工作流校验" + exit 0**（不静默阻断推送）。生成物 chmod +x、幂等覆盖、文件头 `# generated by ocp init --hook`；hook 安装路径经 `git rev-parse --git-path hooks` 解析（兼容 worktree 的 `.git` 文件与 `core.hooksPath`） |
| D3 | pre-push 输入解析 | stdin 每行 `<local_ref> <local_sha> <remote_ref> <remote_sha>`（多 ref 行逐一处理）；diff 文件集 = `git diff --name-only <remote_sha>..<local_sha>`；remote_sha 全零（新分支）降级 `git diff --name-only <local_sha>~1..<local_sha>` + WARN。**奇异形态兜底**：local_sha 全零（删除推送）、无 `~1`（根 commit）、diff 不可解析 → WARN 放行不阻断（fail-open 口径：hook 故障不应硬阻断推送）。**读取口径**：`.stage`/`.stage-history` 读**工作区文件**（正常流程工作区与待推提交一致；异常时 WARN 提示）。**删除路径处理**：topic 判定按"该 topic 目录下至少存在一个非删除 diff 路径"（topic 整目录删除不触发校验） |
| D4 | 代码白名单优先级 | `configs/prepush-config.json`：`codePatterns`（默认 `src/** tests/** scripts/** cli/** check-tools/** agents/** configs/** package.json tsconfig.json bun.lock`）+ `archivePrefix`（默认 `.specpipe/`）。**优先级：白名单命中即代码**——`agents/**` 与 `configs/vendor/**` 中的 .md 以白名单为准（权限与契约文件是行为载体）；其余 `.md`/`README`/`docs/**` 为档案类 |
| D5 | pre-push 校验核心 | `cli/commands/hook-core.ts`（纯函数：diff 文件清单 + 仓库根 → 放行/拒绝+原因）：① 全档案 → 放行；② 含代码 → **topic 提取正则从 archivePrefix 配置派生**（默认 `^\.specpipe/plans/([^/]+)/`，配置改前缀自动跟随，防静默降级）→ **Epic 判定 = 目录含 `epic-spec.md`** → Epic topic 跳过；Story/Issue topic 校验 `.stage===DONE`（文件不存在视为未完成→拒）+ `.stage-history` **存在则逐行 `JSON.parse` 后比较字段**（`from==="QUALITY_GATE" && to==="DONE"`，容错空格/键序两形态——07 卷示例为空格形态、S2 插件写紧凑形态）：**存在但无该行 → 拒**（状态与留痕矛盾）；history 文件不存在 → 放行 + WARN（存量豁免）；③ 代码无 topic → WARN 放行。拒绝输出违规 topic 清单 + 指引（完成质量门或 `--no-verify`） |
| D6 | vendored 副本 | `configs/vendor/specpipe/07-state-machine.md` + `configs/vendor/specpipe/templates/*.md`（九件）入库；`transition-table.json` 新增 `vendor` 段：`{ repo: "https://github.com/jiazhousa/SpecPipe", commit, files: { "<相对路径>": "<sha256>" } }`——**07 卷与 templates 十件全量逐件录哈希**（D13① 对称遍历的前提）。副本由 vendor-sync 生成（本 Story 首次执行产出） |
| D7 | 边集快照 | `configs/transition-snapshot.json`：与 S2 `tests/table.test.ts` 硬编码常量**同构**（states 含 name/path/initial/blocking/terminal/shared 全 flags；transitions 含 from/to/actor/trigger），**比较键**：state=name（flags 全等）、edge=`from→to\|trigger\|actor`（同目标双边靠 trigger 区分）。从测试常量机械提取（一次性脚本），**测试常量不动**（测试第一道对账，快照第二道） |
| D8 | vendor-sync（判据钉死） | `scripts/vendor-sync.ts`：参数 `--path <本地A仓>` 或 `--tag <tag>`（tag 时 clone `vendor.repo` URL 到临时目录，**失败非零退出 + 明确提示**，临时目录用后即删）；流程：读旧 vendor 段 → 复制 07 卷 + templates → 重算哈希更新 vendor 段与 source → **判据：新 07 哈希 ≠ 旧声明 → 输出"契约已变，边集需人工适配（开 B 仓 Story/Issue 走审查）" + 非零退出**（哈希变化本身即需人工流程的信号）；**哈希未变 → 跑快照对账，失败才非零退出**。首跑（无旧声明）视同哈希变化路径处理但提示为"首次基线" |
| D9 | check-tools 结构 | `check-tools/` 每项一个纯逻辑模块 + `cli/commands/check.ts` 薄路由（`ocp check <name>`）：`whitespace.ts` / `line-budget.ts` / `commit-format.ts` / `transition-consistency.ts` / `platform-words.ts`；`check-tools/task-yaml.ts` 占位（S5 预留）。全部可独立 import 测试 |
| D10 | whitespace 规则 | 扫描 codePatterns 范围（单一配置源，沿用 prepush-config）的文本文件：尾随空白（行末空格/Tab）+ 文件末尾缺换行；输出文件:行号:类型 |
| D11 | line-budget 规则（按 06 卷逐类钉死） | `configs/line-budget.json` 规则表（**不设兜底上限**）：`{wf}/plans/*/spec.md ≤300`、`{wf}/plans/*/epic-spec.md ≤500`、`{wf}/plans/*/issue-impl.md ≤80`、`{wf}/reviews/*-epic-spec-revision-*.md ≤40`、`{wf}/reviews/*-spec-revision-*.md ≤30`；**impl.md 与 impl/issue-impl/quality-gate 报告不配规则**（06 卷明确不设上限——B 仓现存 144/130 行合法 impl 报告不可误报）。取终稿口径，草案阶段不检 |
| D12 | commit-format 规则 | `ocp check commit-format [--range HEAD~3..HEAD]`（默认 HEAD 单条）：首行 `<type>: <描述>`，type ∈ {feat, fix, docs, chore, refactor, test, style}（`configs/commit-format.json` 可配置）；描述至少一个 CJK 字符；**merge commit（`Merge`/`Merge branch` 开头）跳过不检** |
| D13 | transition-consistency（三层，① 遍历全量） | ① **遍历 `vendor.files` 全量**逐件重算 sha256 比对（07 卷与 templates 九件都查，非仅 07）；② 数据文件 schema 自校验（状态引用完整性/initial/terminal 存在/边引用状态存在）；③ 快照对账（snapshot ↔ 数据文件，按 D7 比较键双向）。输出逐项 PASS/FAIL |
| D14 | platform-words（词表对齐 S1 禁词集） | `configs/platform-words.json`：`{ words: [...], extraWords: [...] }`——内置初始集**按 S1 impl 禁词表分类纳入**：opencode（独立词）、subagent、SKILL.md、`.opencode`、`~/.config/opencode`、`agents/`、`save_memory`、`MEMORY.md`、`permission.external_directory`、`external_directory`、npm、tmux、角色英文标识（Oracle/Explorer/Checker/Builder/Looker——A 仓角色卷为中文术语，英文残留即平台词）。词形边界匹配。默认扫 vendored 07+templates；**全仓检查以 `--path /path/to/SpecPipe` 指向 A 仓执行**（Epic 验收 6 口径，文档注明） |
| D15 | doctor（输入载体钉死 + 输出形态） | 配置**二级查找**：项目级 `{wf}/doctor-config.json`（`ocp init` 生成默认模板）→ 用户级 `~/.config/opencodepipe/doctor.json`，项目级优先，均无 → 相关项 WARN"未声明"。字段：`retrieval: { primary, fallback, docs }`（三职责位命令名）+ `localARepoPath`（本地 A 仓路径，vendored 对比用）。检查项（各探测函数返回 `{name, level, message}`，**测试对函数级断言**；CLI 支持 `--json`）：git 版本 / opencode 版本与 plugin 段（全局+项目 opencode.json）/ agents 五文件（全局 `~/.config/opencode/agents/` + 项目 `.opencode/agent[s]/`）/ 检索三通道（读声明 + `command -v` 探测）/ vendored 状态（复用 D13 核心 + localARepoPath 对比提示）。**只报告不安装** |
| D16 | init 铺设物 | `{wf}/plans/`、`{wf}/reviews/`、`{wf}/templates/`（vendored 九件复制）、`{wf}/doctor-config.json`（默认模板）、**fence 脚本模板** `scripts/fence.sh`（最小骨架 + 注释指路"按技术栈改写"）、`.gitignore` 追加 `test-fence-reports/`（幂等；**不忽略 `{wf}`**）、`--hook` 装 D2 薄壳（git-path 解析）。已有文件/目录跳过并报告。**B 仓自举 = 仅执行 hook 安装**（避免铺设与 configs/vendor 重复的 templates 与 fence.sh——由调度者以 `ocp init --hook` 执行或块B 任务书指定） |
| D17 | worktree（基准与指引钉死） | `ocp worktree <branch>`：三级格式校验 `^(dev|rel|ms)/(feat|fix|chore)/[a-z0-9-]+$`（`configs/worktree-config.json` 可配置目标集/性质集）；**基准分支默认当前 HEAD**（可配置 target→base 映射：dev→主干分支等）；在专用目录（默认 `../.ocp-worktrees/`，可配置）执行 `git worktree add -b <branch> <dir> <base>`；输出指引对齐 10 卷五步工作流要点（开发→整理 commit→push+MR→rel cherry-pick→ms cherry-pick） |
| D18 | fence 挂载（入口与退出码钉死） | `scripts/run-test-fence.ts` 步骤表追加第四步 **`consistency`**：`bun cli/index.ts check transition-consistency`（子进程 + 退出码判定，0=PASS/1=FAIL）；既有三步语义不变。**全量四步 fence 须块D 收尾后执行**（任务书标注） |
